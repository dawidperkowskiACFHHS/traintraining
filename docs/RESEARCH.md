## Gameplay and content

- [Tuxemon map library](https://github.com/Tuxemon/Tuxemon/tree/development/mods/tuxemon/maps), [database](https://github.com/Tuxemon/Tuxemon/tree/development/mods/tuxemon/db), [graphics](https://github.com/Tuxemon/Tuxemon/tree/development/mods/tuxemon/gfx): examined the content/runtime separation and town/interior file organization. [Azure town’s TMX](https://github.com/Tuxemon/Tuxemon/blob/development/mods/tuxemon/maps/azure_town.tmx) was accessible: orthogonal 16-pixel map, external tilesets and separate layers. This informed a 16-pixel authored-module workflow and explicit collision/interaction separation. No GPL code, tilesets or map layouts copied. Initial guessed `start-town`, `spyder_papertown`, and the raw café file could not be fetched; they were not treated as inspected maps.
- [Question implementations](https://github.com/taibeled/JetLagHideAndSeek/tree/master/src/maps/questions): verified the matching/measuring/radius/tentacles/thermometer organization. The [tentacles source](https://github.com/taibeled/JetLagHideAndSeek/blob/master/src/maps/questions/tentacles.ts) uses geographic Voronoi/radius operations. Here the finite fictional station set permits direct nearest-feature comparison and consistent candidate filtering without Turf, external APIs or geographic projection. Raw radius and thermometer source requests failed through the browsing cache; no unseen implementation was copied or claimed as verified.
- [Map companion](https://github.com/gelbh/jetlag) and [community index](https://github.com/jltg-community/awesome-jetlag-hide-and-seek): reviewed as map/annotation and resource references. Community interpretations are not the rules authority for this game.

## NPCs, maps and routing

- [Yuka](https://github.com/Mugen87/yuka): evaluated its state/goal, steering, navigation and perception building blocks. A small serializable state/goal implementation was chosen for this finite graph and grid game; no general 3D navigation layer was needed. The important integration is the restricted public observation contract.
- [Tiled](https://github.com/mapeditor/tiled) versus [LDtk](https://github.com/deepnight/ldtk): selected Tiled JSON object layers for portable, human-editable original neighborhood rectangles. The runtime consumes the eight archetype layers directly.
- [ProbableTrain MapGenerator](https://github.com/ProbableTrain/MapGenerator): structural reference only. Its output concerns city-map structures and images, not collision-ready adventure towns. No LGPL source copied.
- [JavaScript WFC](https://github.com/kchapelier/wavefunctioncollapse) and [original WFC](https://github.com/mxgmn/WaveFunctionCollapse): evaluated as variation techniques, not a guarantee of connected towns. Authored modules plus explicit global/local reachability checks were more direct here; neither installed.
- [ngraph.path](https://github.com/anvaka/ngraph.path): evaluated graph pathfinding. The small graph uses a custom earliest-arrival Dijkstra implementation because departure waits and transfers are part of the edge cost. No source copied.

## Assets and optional services

- [Superpowers asset packs](https://github.com/sparklinlabs/superpowers-asset-packs) identify Pixel-boy/Sparklin Labs as creators and CC0 as the asset license. The Ninja Adventure example was inspected as an available alternate foundation. Neither pack was copied; original matching travelers, rail props, towns and card illustrations are bundled instead. No blocked asset host or remote runtime dependency is required.
- [AI Town](https://github.com/a16z-infra/ai-town) and [Ollama](https://github.com/ollama/ollama): evaluated as optional dialogue references. No backend, model download or inference dependency installed. All current dialogue and decisions work with conventional local code. Multiplayer and model phrasing remain optional future extensions.

## Focused design review

The review object was the deduction–travel–card loop. Confirmed constraints are shared clock, truthful evidence, hidden positions and card compensation for questions. The main design risk was that broad automatic revelations could turn seeking into following a marker. The implementation keeps true district transitions private, gives logical exclusions their own notebook state, and makes tags depend on actual local sight and reach. A second risk was card collection becoming passive score inflation: the hand limit and two-bonus cap preserve a tradeoff between tools and retained points. The validation experiment is a complete mixed-role match, followed by the human browser scenarios documented in `VERIFICATION.md`. Human enjoyment and long-term balance still require external playtesting; automated completion does not establish those qualities.
